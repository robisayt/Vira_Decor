# Vira Decor — сайт студії дизайну інтер'єру

Преміальний сайт-портфоліо на Next.js 14 (App Router), React 18, TypeScript, Tailwind CSS і Framer Motion.

---

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
```

Збірка продакшену:

```bash
npm run build
npm start
```

Потрібен Node.js 18.17+.

## Як редагувати контент

Уся текстова частина зібрана у двох файлах. Компоненти чіпати не треба.

### `content/site.ts`

- `site` — назва, домен, опис для SEO
- `nav` — пункти меню
- `contacts` — Instagram, Telegram, пошта, телефон (використовуються у шапці, CTA і футері одночасно)
- `hero`, `studio`, `directions`, `principles`, `materials`, `result`, `cta` — тексти секцій

Місця, позначені коментарем `// ЗАМІНИТИ`, містять умовні цифри (кількість проєктів, роки досвіду) — підставте реальні.

### `content/projects.ts`

Один об'єкт — один кейс. Щоб додати проєкт, скопіюйте будь-який об'єкт масиву `projects` і змініть поля:

```ts
{
  slug: "novyi-proekt",        // адреса: /projects/novyi-proekt
  title: "Квартира «Назва»",
  category: "Квартира",         // Квартира | Дім | Кімната | Меблі
  area: "72 м²",
  location: "Київ",
  year: "2026",
  status: "Реалізовано",
  summary: "Один рядок для картки в сітці.",
  description: ["Абзац 1", "Абзац 2"],
  scope: ["Планування", "Дизайн-проєкт"],
  tex: "tex-1",                 // заглушка, поки немає фото
  rooms: "3",                   // необов'язково
  levels: "2",                  // необов'язково
  featured: true,               // показати на головній
}

// Кадр у галереї:
//   span:  "full" — на всю ширину, "half" — у дві колонки
//   ratio: "wide" | "classic" | "landscape" | "square" | "portrait"
// Якщо не вказано — працює автоматична розкладка.
```

Сторінка кейсу, картка в сітці й фільтри оновляться автоматично.

## Як підставити фото

Поки фото немає, компонент `Frame` малює шарову текстуру з палітри бренду — сайт ніде не виглядає порожнім.

1. Покладіть знімки у `public/projects/<slug>/` (як у `public/projects/antresol/`).
2. Додайте шляхи в `content/projects.ts`:

```ts
cover: "/projects/antresol/cover.jpg",
gallery: [
  { src: "/projects/antresol/living.jpg", caption: "Медіазона вітальні", tex: "tex-4", span: "half" },
],
```

Розмітка не зміниться — заглушка просто поступиться місцем фото.

Для блоку «Було / Стало» передайте у компонент `BeforeAfter` пропси `beforeSrc` і `afterSrc`.

## Розділ «Меблі»

Сторінка `/mebli`, дані — у `content/furniture.ts`. Описів на сторінці навмисно немає:
лише назва категорії і галерея.

### Додати фото

1. Покладіть знімки у `public/furniture/<slug>/` (папки вже створені).
2. Додайте шляхи у потрібну категорію:

```ts
{
  slug: "kitchens",
  title: "Кухні",
  photos: [
    { src: "/furniture/kitchens/01-walnut-island.jpg", w: 960, h: 1280 },
    { src: "/furniture/kitchens/02-walnut-herringbone.jpg", w: 519, h: 1152 },
  ],
}
```

`w` і `h` — справжні розміри файлу в пікселях. Галерея вирівнює кадри по висоті
ряду і рахує ширину з цих чисел: широкий загальний план займає пів ряду,
вертикальний — вузьку колонку.

Єдиний виняток — `MIN_AR` у `components/furniture/FurnitureGallery.tsx` (0.56).
Знімок 9:20 з телефона у справжніх пропорціях дав би 6–7 кадрів у ряду завширшки
150 px, тобто стрічку мініатюр. Такі кадри показуються як 9:16: обрізається по
10% зверху і знизу — стеля і підлога. Решта пропорцій не змінюється.
Щоб показувати всі кадри без обрізання, поставте `MIN_AR = 0`.

Розміри можна дізнатись командою:

```bash
python3 -c "from PIL import Image;import sys;[print(f, Image.open(f).size) for f in sys.argv[1:]]" public/furniture/kitchens/*.jpg
```

Порядок у масиві = порядок показу. Щоб переставити фото — переставте рядки.
Заглушки зникають автоматично, щойно в категорії з'являється хоч одне фото.

### Додати категорію

Додайте об'єкт у `furnitureCategories` і створіть однойменну папку в
`public/furniture/`. Секція, якір у навігації зверху й нумерація підтягнуться самі.

## Ілюстрації в блоці «Напрями роботи»

`components/illustrations/DirectionArt.tsx` — п'ять лінійних ілюстрацій в одному
модулі 400×400: інтер'єр, план квартири, куб-перспектива, шафа по деталях, кошторис.

- **Desktop**: при наведенні на картку лінія малюється послідовно (Framer Motion
  `pathLength`, тобто ті самі `stroke-dasharray`/`stroke-dashoffset`), після
  завершення проявляються дві напівпрозорі заливки. Попередня ілюстрація гасне,
  нова малюється — без мерехтіння.
- **Мобільні**: анімація не запускається взагалі, показується готовий малюнок у
  спрощеному варіанті (`compact` — лише перші 10 ліній, без дрібних деталей, які
  на 100 px усе одно зливаються).
- `prefers-reduced-motion` вимикає малювання і показує фінальний стан.

Товщина ліній — `vectorEffect="non-scaling-stroke"`, тому вона однакова і в
великому прев'ю, і в мобільній мініатюрі.

Щоб змінити малюнок — правте масив `STROKES`: порядок рядків = порядок малювання.

## Якість фотографій

Це стандарт проєкту — він застосовується до кожного нового кейсу автоматично,
нагадувати не треба.

### 1. Вихідники

```bash
npm run photos -- <slug> ~/renders/*.jpg
```

Скрипт `scripts/prepare-photos.mjs` кладе файли в `public/projects/<slug>/`:
рідна роздільність (обрізається лише те, що більше 2560 px), JPEG q94,
без субдискретизації кольору (4:4:4), mozjpeg.

Субдискретизація — головна причина «мильності» на рендерах: вона усереднює колір
сусідніх пікселів і першими зникають межі каменю, тканини й тонкі профілі.

**Не зменшуйте фото заздалегідь** до 1200–1500 px і не зберігайте з якістю 75–80.
Це вихідники, користувач їх не бачить — з них `next/image` віддає AVIF потрібного
розміру. Втрачені на цьому кроці деталі повернути вже неможливо.

### 2. Віддача

- `next.config.mjs` → `formats: ["image/avif", "image/webp"]`. AVIF тримає фактуру
  значно краще за WebP при тій самій вазі.
- `sharp` у залежностях — саме він стискає зображення в проді. Без нього Next
  падає на повільніший WASM-фолбек із гіршим результатом.
- `quality={94}` на кадрах проєкту. Дефолт Next — 75, і саме він давав розмиту
  картинку: вихідник перекодовувався вдруге з великою втратою деталей.
- Точний `sizes` на кожному кадрі. Занижений `sizes` — друга типова причина
  розмитості: браузер бере надто маленький файл і розтягує його. Особливо помітно
  на планшетах, де сітка вже дві колонки, а `sizes` ще каже 33vw.

### EXIF-орієнтація

Фото з телефона майже завжди зберігаються горизонтально плюс тег повороту в EXIF.
Якщо його не застосувати, знімок ляже боком. `scripts/prepare-photos.mjs` викликає
`.rotate()` без аргументів — це застосовує EXIF і прибирає проблему. Якщо готуєте
фото іншим інструментом, переконайтесь, що поворот «вшитий» у пікселі.

### Кадрування конкретних фото

Компонент `Frame` приймає `position` (це `object-position`). Використовуйте його,
коли важливо, яка частина кадру видима після обрізання:
`position="left bottom"` тримає акцент внизу ліворуч (як у Hero),
`position="center"` центрує (як фото салону у блоці «Про студію»).

### 3. Пропорції кадру

У галереї кожен знімок отримує рамку під себе, щоб `object-cover` не різав
композицію: `ratio: "wide" | "classic" | "landscape" | "square" | "portrait"`
(16/9 · 3/2 · 4/3 · 1/1 · 4/5). Вертикальні кадри варто ставити поруч —
тоді ряд не «провалюється».

### Стеля якості

Різкість обмежена роздільністю вихідних рендерів. Файли 2000–2300 px по довгій
стороні повністю покривають телефони й ноутбуки, але на великому 4K-моніторі
кадр на всю ширину вже працює на межі. Якщо є оригінали більшого розміру —
перезберіть їх скриптом, решта пайплайну готова.

## Логотип і мереживо

З наданих файлів підготовлені асети в `public/`:

| Файл | Де використовується |
| --- | --- |
| `logo.png` + `logo-sm.png` | великий логотип у hero (desktop / телефон) |
| `logo-light.png` + `logo-light-sm.png` | футер і темні секції |
| `mark.png` + `mark-sm.png` | круглий знак VD у шапці при скролі |
| `mark-light.png` + `mark-light-sm.png` | той самий знак у відкритому мобільному меню |
| `lace.png` / `lace-light.png` | вертикальне кружево — водяні знаки, hero, футер |
| `lace-v-sm.png` / `lace-v-light-sm.png` | кружево на «нитці» зліва |
| `lace-h-sm.png` / `lace-h-light-sm.png` | горизонтальне кружево — розділювачі секцій |

### Чому окремі файли для малих розмірів

`next/image` перекодовує зображення у WebP і на малих розмірах з'їдає волосяні лінії
логотипа й кружева. Тому фірмові зображення виводяться через
`components/ui/Picture.tsx` — звичайний `<picture>` без перекодування, з окремим
файлом для телефонів. Малі версії згенеровані з оригіналів LANCZOS-зменшенням
із компенсацією прозорості, щоб тонкі лінії не «вигоряли».

Якщо будете міняти логотип — покладіть новий файл і згенеруйте зменшену копію
(приблизно 2–3× від розміру, у якому він показується), інакше на телефоні
знову зникатимуть тонкі елементи.
| `favicon.ico`, `app/icon.png`, `app/apple-icon.png` | монограма VD на бордовому тлі |

Логотип не перемальовувався — з нього лише вирізані елементи та зроблені прозорі й світлі версії.

### Розділювач секцій

`components/ui/Divider.tsx` — лінія · кружево · лінія. Пропси: `variant` (`dark` / `light`)
і `size` (`sm` / `md`). Використовується на стиках великих секцій — навмисно не частіше,
щоб прийом не знецінився.

## Фірмовий елемент — «мереживна нитка»

`components/layout/Thread.tsx` — тонка вертикальна лінія зліва (від 1024px), по якій разом зі скролом рухається мереживний медальйон. Той самий мотив повторюється в `Divider` між секціями, у водяних знаках і в мобільному меню. Це те, що робить сайт впізнаваним і пов'язує його з логотипом.

## Структура

```
app/                       сторінки (App Router)
  layout.tsx               шрифти, метадані, шапка/футер/нитка
  page.tsx                 головна — просто список секцій
  projects/page.tsx        сітка проєктів
  projects/[slug]/page.tsx кейс
components/
  layout/                  Header, Footer, Thread
  home/                    секції головної (кожна самодостатня)
  projects/                картка і сітка з фільтрами
  ui/                      Button, Frame, Reveal, Divider, Counter,
                           SectionLabel, BeforeAfter
content/                   увесь текст і дані проєктів
lib/                       cn(), спільні варіанти анімацій
public/                    логотип, мереживо, іконки, майбутні фото
```

Щоб переставити секції на головній — змініть їхній порядок у `app/page.tsx`.
Щоб додати сторінку (наприклад «Послуги») — створіть `app/services/page.tsx` і додайте пункт у `nav`.

## Кольори і шрифти

Палітра описана один раз у `tailwind.config.ts` і продубльована змінними в `app/globals.css`:

| Токен | Hex | Роль |
| --- | --- | --- |
| `porcelain` | `#FEFEFE` | основний фон, повітря |
| `linen` | `#F7F4F4` | фон секцій, що чергуються |
| `dust` | `#D6CCCD` | світлі градієнти, м'якість |
| `mauve` | `#B6A3A5` | пудрові переходи |
| `clay` | `#917371` | лейбли, волосяні лінії |
| `taupe` | `#81666B` | основний текст абзаців |
| `wine` | `#60242C` | кнопки, акценти, CTA-секція |
| `ink` | `#2B1E20` | темні секції, заголовки |

Шрифти підключені через `next/font/google` (з кирилицею, без зовнішніх запитів у рантаймі):
**Cormorant Garamond** — заголовки, цифри, назви проєктів, пункти меню;
**Manrope** — основний текст, лейбли, кнопки.

### Про українські літери

Симптом був такий: і, ї, є, ґ виглядали жирнішими за решту тексту. Це не «шрифт
поганий» — це підстановка з системного фолбеку: у **Jost** кирилиця неповна, і
браузер брав саме ці чотири знаки з іншого шрифту. Тому замінений лише Jost.

**Manrope** підібраний під ту саму задачу: кирилиця рідна для сімейства (не додана
згодом), українські знаки намальовані в тій самій вазі, характер — стриманий
журнальний гротеск, який тримає розріджені капітельні лейбли й не сперечається
з Cormorant.

Якщо після збірки і, ї, є, ґ все ще вибиватимуться — значить проблема була не в Jost,
а в Cormorant Garamond. Перевірити просто: подивіться на заголовок «Простір,
продуманий до сантиметра» і на слово «інтер'єру» в тексті — де саме літери жирніші.
Якщо в заголовках, замініть у `app/layout.tsx` дисплейний шрифт на `Cormorant_Infant`
або `Playfair_Display` (обидва з тим самим високим контрастом, але іншою кирилицею).

## Доступність і продуктивність

- Мобільна версія — пріоритет: тап-таргети від 52 px, кнопки на всю ширину, у блоці «Напрями» спершу три пункти й кнопка «Показати більше».
- Кнопка повернення нагору — кругла, з кільцем прогресу прокрутки (`components/ui/ScrollToTop.tsx`).
- Під відкритим мобільним меню сторінка не прокручується: body фіксується і позиція
  повертається після закриття (`overflow: hidden` в iOS Safari не працює).
- Якірні пункти меню (`/#directions`, `/#contact`) спершу знімають блокування прокрутки,
  потім плавно ведуть до секції — і з головної, і з інших сторінок.
- Desktop має власну композицію (інша сітка, прев'ю напрямів, hover-стани) і навмисно ущільнені відступи — менше прокрутки.
- `prefers-reduced-motion` вимикає анімації.
- Видимий фокус на клавіатурі, посилання «Перейти до вмісту», `aria`-атрибути на слайдері й меню.
- Декоративні зображення позначені `aria-hidden`, оптимізовані через `next/image`.
